# Volatility Modelling and Risk Management of Amazon (AMZN) Returns

[![CI](https://github.com/Jesusgonzmar/amzn-volatility-risk/actions/workflows/ci.yml/badge.svg)](https://github.com/Jesusgonzmar/amzn-volatility-risk/actions/workflows/ci.yml)
![R](https://img.shields.io/badge/R-%E2%89%A5%204.1-276DC3)
![License](https://img.shields.io/badge/license-MIT-green)

An end-to-end financial econometrics project in **R** with a written report in **LaTeX**. It analyses the daily log returns of Amazon (AMZN) over 2019–2021: descriptive statistics, stationarity, ARMA and neural-network forecasting, GARCH volatility modelling, and Value at Risk (VaR) / Expected Shortfall (ES) estimation.

The full write-up is in [`report/main.tex`](report/main.tex) (compiled by CI as a downloadable PDF artefact).

## Key findings

| Topic | Finding |
|---|---|
| Distribution | Returns are stationary, with a mean statistically equal to zero, and **leptokurtic** (sstd shape ≈ 5.2); normality is rejected (Jarque–Bera). |
| Mean model | ARMA(1,1) beats MA(1) on AIC; a non-linear **NNAR(13,7)** achieves the lowest out-of-sample RMSE. |
| Volatility | Significant ARCH effects (ARCH-LM, lags 4–16). An ARMA(1,1)–sGARCH(1,1) with skewed Student-*t* innovations removes them; α₁ + β₁ = 0.9846, i.e. **highly persistent** volatility. |
| Risk (95%, 1 day) | VaR: Gaussian −3.06%, historical −2.90%, modified −2.93%. ES: Gaussian −3.87%, historical −4.21%, modified −4.20%. **Gaussian measures understate tail risk.** |

> These figures come from the original analysis run. The scripts regenerate every table and figure; small differences may appear on re-running (for instance in the neural-network results).

## Methodology

1. **Data**: adjusted close prices from Yahoo Finance via `quantmod`; log returns; chronological 80/20 train/test split.
2. **Descriptive analysis**: moments, Jarque–Bera, ADF, Ljung–Box, EACF.
3. **Mean models**: MA(1), ARMA(1,1), `auto.arima`, NNAR, compared out of sample by RMSE against a zero-forecast benchmark.
4. **Volatility**: Engle's ARCH-LM test, then ARMA(1,1)–sGARCH(1,1) (`rugarch`) with post-estimation diagnostics and a test of symmetry (H₀: ξ = 1).
5. **Risk**: Gaussian, historical and Cornish–Fisher VaR/ES; 500-day rolling window; exceedance check with the Kupiec test.

## Getting started

**Requirements:** R ≥ 4.1 and a LaTeX distribution with `latexmk` (TeX Live or MiKTeX).

```bash
git clone https://github.com/Jesusgonzmar/amzn-volatility-risk.git
cd amzn-volatility-risk

make install    # install the R packages
make analysis   # run the pipeline: downloads data, writes outputs/, figures and tables
make report     # compile report/main.pdf
```

Without `make`, run `Rscript R/install_packages.R`, then `Rscript R/run_all.R`, then `cd report && latexmk -pdf main.tex`. Run all commands from the repository root. The report compiles even before the analysis has been run; missing figures and tables are replaced by placeholders.

Prices are downloaded once and cached in `data/`. They are not committed because of Yahoo Finance's terms of use.

## Limitations and possible extensions

- A single asset over a short window that includes the COVID-19 shock.
- Multi-step forecasts over the whole test sample; a rolling one-step-ahead evaluation (with a Diebold–Mariano test) would be more informative.
- Static VaR/ES are in sample, and the rolling VaR is not GARCH-based. Backtesting covers unconditional coverage only (no Christoffersen independence test).
- Extensions: EGARCH / GJR-GARCH, GARCH-filtered VaR and ES, multi-asset portfolios.
